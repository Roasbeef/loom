# The web view against the final mockup: the difference list (2026-11-24)

The owner's first ask is 100% fidelity to `final/mockup.html`, with no
attachment to the earlier versions. This note lists every difference found by
setting the running page beside the mockup's own frames, and gives each one a
disposition. A difference is either **Fix** or **Departure**. A departure stays
only where a ruling or a security rule requires it, and the row names which. A
row marked **Owner** is a departure the mockup does not argue for and no ruling
requires; it stays until the owner decides, and the recommendation is stated.

The fixes land in the slices at the end. Each slice is its own PR with captures
beside the mockup frame.

## 1. How the comparison was made

A fresh daemon at `main` (`a424e6ac6`) with its own state directory and port,
started by `scripts/web_seed/seed.sh` and then seeded with these sessions
through the page's own composer:

| Session | What it holds |
|---|---|
| `vetting lint` | An approval (`need network`), then the advisor's nudge and a long answer. |
| `lint census` | An open ask with two questions (`ask me first`). |
| `fix/hashline-replay` | Worktree hunks in two files and a risk notice (`make changes`, `post a notice`). |
| `work/slowly` | A 45 s turn, so the session is running and has an Update (`work slowly`). |
| `sub/go-stuck` | A sub-agent whose provider refuses the request: a stuck strand (`go stuck`). |
| `docs/threat-model` | Idle, nothing to say. |
| Project `loom` | Ticket `t-r1` at `person/answer` and `t-r2` at `person/check`. |

The mockup was opened with `?theme=dark` and its own query parameters
(`open=`, `view=live&s=`, `sheet=open`, `demo=staged`). Both were captured in
Chrome for Testing at 1440x900 and 375x812. Captures are under
`~/loom-drives/fidelity/<page>-<state>-{mock,app}-<width>.png` and are not
committed.

**Not captured in this pass.** The seed has no saved, blocked, failed-start,
moving or relayed session, no coordinator with delegates, no peer message to an
approval's session, and no second observer. Those frames (mockup coordinator
ask, live coordinator, live repair with a peer insight) are compared from the
mockup's source and the code, and each row says so. Slice 4 extends the seed and
captures them before it changes them.

restyled to the mockup's visual language: the sidebar toggle, Search, the Owner
menu, Admin, `All sessions`, the session page's tabs and strand cards, and the
attach `+`. Rows F2, F9, L6, V2, V3, V10 and V12 that read **Owner** are therefore
settled as departures, and only their restyle remains. On the session page the
right column opens on the "Lifted from this session" rail (Needs you, then
Insights) at 344 px, with the tabs after it and the strand cards folded to one
row per strand with no avatar. The "· 14 messages" count (K6) is left out
because the feed does not carry it. The Projects section on Home (F1) belongs to
the project-page work and is not changed by these slices.

**Slice 1, rail and inbox list.**

- F3, F4: the rail's default width is 184 px (`grip_rule.sidebar_default_width`
  and the stylesheet's fallback); a width the reader dragged is kept.
- F2: the bar is 44 px.
- F5: Needs you, To review, Finds and Updates are always listed, with a count
  of 0 drawn as text, not a button, since a press on an empty folder changes
  nothing; Projects is listed only while a ticket waits.
- F6, F7: the running sessions are one flat list under "Watch live", and the
  session's last prompt is no longer a third line. The saved, blocked and
  orchestrator groups keep their headings, which the mockup has no frame for.
- L1: a sub-agent's row is named `sub:<purpose>`, without its parent and its
  sixteen digits. Two siblings of one purpose now read alike on a row.
- L2, L3: already built (`thread_words.overdue`, an hour or more is amber); the
  first capture had no row that old.
- L7: **not done; a departure that needs a feed field.** The row's subject for
  an approval is still the session's last message. The page reads an approval's
  evidence only for the thread that is open, so a subject drawn from it would
  change when a row is pressed, and the feed's row (`sessions.Report`) does not
  carry the approval's tool or request. A subject of `bash · wants a network
  grant` needs the feed to carry them.
- F5, F6: the rail's folder list differs by page. A session page and the admin
  page list all six folders (they pass no counts); Home lists the four always-on
  folders with their counts and Projects while a ticket waits. The running
  groups are not given a heading in the tree, and each section names itself to
  assistive technology. The session's last prompt stays in the tree and is
  hidden by the stylesheet, because the session switcher reads it.
- L1: the strand name comes from `session_view/strand_name.short`, the same cut
  the live page uses.

**Slice 2, thread panes (on top of slice 1).**

- A1, K8: a session thread's eyebrow is `<session> · main · <project>`, the
  project being the workspace's directory name and not its path. An ask, find or
  stuck record's eyebrow is `<session> · main`, or `sub:<purpose> · under
  <session>` for a delegate.
- A7, S3: the message box is headed `Or message <name>` (`Add a message to
  <name>` for an ask, `Message <name>` for an update), where the name is the
  session's or the delegate's.
- A9: Clear is drawn only while something is staged.
- K1: the coordinator card counts delegates other than `main` and `advisor`, so
  an ordinary session no longer draws one for its advisor.
- K4: Other carries no number.
- S2: Retry is the mockup's option card: number, label, `recommended` and `Sends now,
  exactly: “...”`. Dismiss stays a small button beside it (protocol-change/131).
- T4: a ticket's question section is headed `The worker's question`, without its
  internal number.
- Left for later slices: K5 (staging an answer on the option's press, which
  needs the answer form to stage on change), K6, K2's single heading for a
  multi-question ask, A3, A5, A6, T1 to T3, T5 and U2.

**Slice 3, the session page.**

- V2: at 980 px and up the right column opens on "Lifted from this session"
  (Needs you, then Insights) and the tab bar follows it, on every tab. The
  column scrolls as one and the tab bar sticks under the rail. The rail is
  still the Strands pane's first child in the document, so no handler path
  moves; the stylesheet gives the boxes between it and the tab bar no box.
- V3: a strand is one row, name and status, with no avatar and no model line.
- V1: the head's first line is the dot, the name, the place, the state and
  the goal, as the mockup draws it. The figures and the placement chips follow
  on a second quiet line.
- V5: an insight's head stops at two lines; the stream row holds the whole
  text.
- Watch live (the rail's rows) and Watch it live (a thread's button) both open
  the session's page, whose column now opens on the rail.
- Not done: V6 (each rule only when its kind is on the page), V7 (stream
  gutter), V10 (composer hint row) and V12 (the crumb's project word).
