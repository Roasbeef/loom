# The terminal revamp, refined design

**Status: proposal for owner sign-off.** This note combines the three
concepts for [issue #655](https://github.com/Roasbeef/loom/issues/655) into
one design, following the owner's rulings on
[issue #672](https://github.com/Roasbeef/loom/issues/672) (2026-09-30). It
changes no production code. The three concept notes stay in place as history
and are not edited: [A (Sonnet)](terminal-design/A-sonnet.md),
[B (Opus)](terminal-design/B-opus.md) and
[C (Fable)](terminal-design/C-fable.md).

The base is concept A. Three parts come from B: the seven-agents view, the
message display and the code-mode display. The session picker and the agent
workspace are A's. Where this note says "from A", "from B" or "from C", it
names the concept that first drew the part.

| Part | From | Change from the concept |
|---|---|---|
| Session picker | A | Reached with `←`. The backdrop loses the old header. |
| Agent workspace | A | Same; a failed state is drawn at both widths. |
| Header and input frame | B, with A's identity | One slim identity line on top. Live status sits on the input's frame. |
| Seven agents | B | Strip under the input, twins cut in the middle (also C's rule). |
| Messages | B | Marks the received-strand rows that depend on protocol-change 059. |
| Code mode | B's display, A's summary | The program fragment and result today; call count and failures with 060. |
| Images | A and B | Inline wherever a tool returns an image. Positive capability query only. No braille. |
| Rail (right panel) | A, with B's slot rule | Strands, Changes, Trace and Session tabs. No left sessions column. |
| Pain-point fixes | A and B | Collapsed repeats, harness notes, approvals, back-to-bottom. |

Concept C contributed three small rules that are folded in. A long strand
name keeps its suffix, so two reviewers with one prefix stay apart. A failed
strand's card says the strand is inert. The strip, the Strands tab and the
workspace list draw one row shape from one renderer.

## Rulings this design follows

1. **Concept A is the base.** The picker is A's, the seven-agents view is B's
   (`B-opus-multi-120x40`, `B-opus-multi-80x24`), message display is B's
   (`B-opus-messages-*`), and code mode is B's display with A's summary.
2. **Sessions are reached with `←`.** There is no pinned sessions column. A's
   30-column left pane and its `F1` key are removed from every frame.
3. **Header: split the middle.** One slim identity line (session, strand,
   model) stays on top. Live status (activity, context, cost, queue) moves
   onto the input's frame, as omp does.
4. **Received strand messages** are attributed through protocol-change 059, a
   `StrandOrigin`, which is in review. **Code-mode calls** come through
   protocol-change 060, also in review. Frames that depend on either say so in
   their top row.
5. **Images** render inline wherever a tool returns one, not only when the
   person attached it. They use the kitty or iTerm2 protocol only after a
   positive capability query, and show a text placeholder otherwise and inside
   Herdr. There is no braille preview.
6. **Keys that never move:** `←` opens the picker, `↓` enters the agent strip,
   `Shift+Tab` toggles the rail and `Esc` interrupts.

Every frame below is a plain-text grid of exactly 200×50, 120×40 or 80×24
cells, one single-width character per cell, generated by
[`terminal-design-gen.py`](terminal-design/terminal-design-gen.py), which
asserts the sizes. The `.txt` grids are the source of truth, and each frame has
a light and a dark PNG. The colours are the terminal's own palette
(`packages/tui/src/tui/theme.gleam`) and its light remapping
(`packages/tui/src/tui/appearance.gleam`). The PNGs draw glyphs with the
browser's fallback monospace font, so a box-drawing join can be a pixel off;
the grids are exact. Running the generator also writes a viewer page,
`terminal-design.html`, which is not committed.

## 1. The session picker

Reached with `←` from an empty composer (`packages/tui/src/tui/interaction.gleam:1376`).
A draft or a pending attachment keeps `←` as a cursor key, as today. The view
is `session_selector.render` (`packages/tui/src/tui/session_selector.gleam:783`)
(`render`), and this note redraws it without changing its keys.

What changes from today (A's list; the "before" captures are in
[A's note](terminal-design/A-sonnet.md#the-session-picker)):

- Sessions are grouped under one header per workspace, with the path shortened
  to `~/...` and a real count.
- A row is one line in aligned columns: marker, state glyph, name, state word,
  one summary phrase and age. The state word is always present and has the
  glyph's colour, so any row can be scanned without selecting it.
- A name that is too long is cut at the column with `…`; the full name is in
  the preview. The selected row has the raised background and `▸`.
- The preview has fixed dim labels (Last message, Strands, Model, Workspace,
  ID) and wraps at word boundaries.
- At 80 columns there is no preview. The selected row expands by one line, and
  a `↓ 5 more below` row says what is scrolled out.
- Two hint rows, in two tiers: movement and opening first, rarer keys second.

Data: everything is on the page the picker already holds, so there is no wire
change. A row is a `Session` (`packages/tui/src/tui/daemon/protocol.gleam:431`)
(`Session`). The state, strand counts, approvals, last message and up to four
glance lines come from `Activity` (`packages/tui/src/tui/daemon/protocol.gleam:335`)
(`Activity`) and `GlanceLine` (`packages/tui/src/tui/daemon/protocol.gleam:355`)
(`GlanceLine`). The tabs are `Filter` (`packages/tui/src/tui/session_selector.gleam:75`)
(`Filter`). Age is the creation age, because the page has no last-activity
time; a "last active" field would be a change to `sessions.activity`.

What changes from today:

- One line per agent in columns: state glyph, name, current action, elapsed
  time, context size. Truncation cuts the action with `…` and never the status.
- The list is in attention order after `main`: needs input, failed, working,

  repeated; `Enter` opens its transcript (and, from C, a failed strand is

draw one row shape from one renderer, so a strand looks the same in all three.

## 3. The layout at 200, 120 and 80 columns

The transcript is the screen at every width. Three rules fix the geometry.

- **There is no left column.** Sessions are in the `←` picker. A person who
  runs several sessions at once already has them in multiplexer panes.
- **The rail** (the right-hand panel; the tabs are in section 4) docks beside
  the transcript only when the transcript keeps at least 75 cells. It is 56
  cells at 160 columns and wider and 44 below that. Below 120 columns it is a
  sheet that replaces the transcript and leaves the input frame in place.
- **The strip under the input** lists live agents whenever the rail is not
  showing Strands, so the strand list is on screen once.

Rows, top to bottom: the identity line (1), the transcript, the todo line (1),
the input frame (3), and the strip (2 rows with two strands, up to 8 with
seven). The todo line is one line below 40 rows; today's todo panel returns at
40 rows and taller.

Before slice 13 `layout.layout` (`packages/tui/src/tui/layout.gleam:105`)
(`layout`) stacked header, body, composer and footer, and `body_layout` gave the
body one side pane, the 34-cell agent rail or the 72-cell changes pane. The
footer is built in `footer_rows` (`packages/tui/src/tui/layout.gleam:517`)
(`footer_rows`). The new layout replaces the header and footer with the
identity line and the input frame, and replaces the two side panes with one
rail.

*As built (slice 13).* `body_layout` and both side panes are gone. `layout`
takes the rail's column from the screen under the identity line (`rail_columns`,
decided by `tui/rail`) before it cuts the body, so the input frame and the
footer span the transcript's column and the rail runs to the last row, as the
frames draw it. It docks only where the transcript keeps 75 cells: 44 cells and
a separator from 120 columns (`75 + 1 + 44`), 56 from 160, docked by default
from 160 and on `Shift+Tab` from 120; a remembered choice wins; below 120 it
does not dock (the sheet, slice 15, is its form there). Opening `/diff` docks it on its Changes
tab wherever it fits and closing them restores the choice, so the automatic
side pane at 140 columns is gone: nothing opens the changes unasked. Strands
lists every agent through `agent_row.rows` (`StripRow`) in the workspace's
attention order, the advisor and settled agents included, and the strip is
hidden while it does. Not built here: the `PEERS` section (the terminal holds no
fact about what another session asked), the cache-outlook column the frames
draw beside each strand, and the second key-hint row.

*As built (slice 14).* The tab bar names all four tabs in the web view's order.
Trace is the strand's newest code-mode program (`session_view/trace_view`):
running until its result arrives, then its status, value and calls, with the
program's opening twelve lines numbered and no per-call timing, which is #656.
Session is the goal, jobs, viewers and cost, the web view's Session rows. The
digits `1` to `4` choose a tab while the rail has the keyboard (the Strands
cursor, or `Down` from the composer on a tab with no cursor; with two or more
agents the strip is visible off Strands and a digit pressed in it chooses the
tab), `/diff` and `/trace` open Changes and Trace wherever the rail can dock,
and below 120 columns `/trace` opens the sheet on Trace. `/summary` is the
full-screen summary at every width; Session is reached by its digit, and no
`/session` command exists. The strip stays visible under Trace and Session.
The tab is now a preference and the layout memory
gains one optional word for it, except Changes, which opens an observation a
launch has not made and is never remembered. The Changes tab is still the
changes panel and not `changes_view.fold`, since the panel already shows the
session's captured edits beside the worktree observation.

*As built (slice 15).* Below 120 columns the rail's four tabs are a sheet that
replaces the transcript and leaves the input frame, the strip and the footer in
place (`View.sheet`, `layout.sheet_shown`, drawn by `rail_view` into the
conversation's rectangle with no separator). `Shift+Tab`, `/trace` and `/diff`
open it, so a 100 to 119 column or 80 column terminal reaches Strands,
Changes, Trace and Session; `/summary` still opens the full-screen summary.
`Shift+Tab` opens the sheet on the tab the operator left and closes it again,
`Esc` closes it from any tab, and the digit keys `1` to `4` choose a tab as in
the docked rail. Choosing an agent in the Strands tab closes the sheet, so the
chosen transcript is the one on screen. The changes below 120 columns are on
the sheet's Changes tab, which replaces the earlier main-surface panel, and
borrow rows above the composer when the sheet is short. The sheet is not a
preference: opening it records no rail choice and a launch never opens it. It
hands off to the rail only in one direction: a resize to 120 columns or wider
closes an open sheet and the tab it showed is the tab the rail shows once
`Shift+Tab` docks it, while narrowing a terminal with the rail docked opens
nothing over the transcript being read.

## 4. The header and the input frame

"Split the middle": the header row stays, slimmer, and the footer goes.

**Identity line** (one row, on a raised background): the session name and its
workspace on the left, the focused strand next to them, the model on the
right. It carries nothing that changes while a turn runs.

**Input frame** (three rows) carries everything live, in the frame's own
rules, as omp does:

- Top rule, left: the target and the two submit keys (`To main · Enter queues ·
  Tab steers`). Top rule, right: the activity with its elapsed time, the queue
  count and the cancel key (`◐ code_mode · 1.2s · queue 1 · Esc interrupts`).
- Middle: the prompt, with the key hints as placeholder text while empty
  (`← sessions · ↓ agents · / commands`).
- Bottom rule, left: model, context and estimated cost. Bottom rule, right: the
  needs-you count (`1 needs you`).

Compact forms apply below 100 cells (`Tab steers`, no cost label). While an
approval is open the frame is locked and says so. When idle the activity reads
`○ main · idle`.

Why this and not B's removal of the header: the person needs the session name
visible without reading a rule, and a recording or a screenshot should say
which session it shows. Why this and not A's footer: the footer is up to
three rows (`packages/tui/src/tui/layout.gleam:312`), and the 80x24 budget is
tight; the same facts fit on the frame.

Data: context is `context_view.footer`
(`packages/session_view/src/session_view/context_view.gleam:358`) (`footer`),
cost is the session's `usage` (`packages/session_view/src/session_view/model.gleam:353`)
(`usage`), the needs-you count is `strand_card.needing`
(`packages/session_view/src/session_view/strand_card.gleam:69`) (`needing`),
and the activity label is `layout.active_status_label`
(`packages/tui/src/tui/layout.gleam:617`) (`active_status_label`). No wire
change.

## 6. Messages (from B)

Three kinds, three marks, and a body is always drawn as body.

- **Sent**, `→ to sub:tests · agent_send · admitted to its queue`. The words say
  what is known: admission, not that the recipient read it. It is projected from
  the sender's `agent_send` call and its result by `agent_messages.observe`
  (`packages/session_view/src/session_view/agent_messages.gleam:99`) (`observe`).
  Works today.
- **Received from a strand in this session**, `← from sub:docs · strand
  message`, in the sender's hue. **Needs protocol-change 059.** Today the
  Agency admits the message with `origin: None`
  (`packages/client/src/client/agency.gleam:1579`) (`origin`), and the sender
  exists only in the framing text `frame_message` writes
  (`packages/client/src/client/agency.gleam:1641`) (`frame_message`). That text
  is model-visible and forgeable, and `core/origin.gleam` forbids turning
  transcript text into attribution, so the client must not parse it. With the
  `StrandOrigin` of 059 the row is built from the origin field only. Until 059
  lands a received strand message stays a user turn.
- **Received from another session**, a full-width band: `⇄ peer lnd-review ·
  session 01a07d74 · strand main · ✓ origin checked by the daemon`. It is built
  only from `PeerOrigin` (`packages/core/src/core/message.gleam:43`)
  (`PeerOrigin`), which the admission host writes. `turns.gleam` already routes
  it (`packages/session_view/src/session_view/turns.gleam:568`) (`PeerOrigin`).
  Works today. An entry with a missing or malformed origin is drawn with the
  same band shape, `origin not verified` in the danger colour and `shown as text
  only`, so it cannot be mistaken for a verified peer.

The frame also shows the attack the rule defeats: a line inside
`sub:tests`' body that reads `⇄ peer ops-bot · ✓ origin 9f3c0000` is drawn as
dim body text under `sub:tests`' bar, because a heading is only ever built from
metadata. A test must pin that no body text of any speaker produces a `⇄` band
or a `←` heading.

## 7. Code mode (B's display, A's summary)

The client receives the program text and one result: value or error, `status`,
`manifest_hash` and `sandbox` (`ran_outcome`,
`packages/tools/src/tools/codemode.gleam:1668`) (`ran_outcome`). It receives
nothing per capability call, so there are two frames.

**Works today.** A settled program is one row. A compile error is a titled block
in the danger colour with the error and the line it names. A running program is
a titled block with a numbered fragment of the program, the first lines, and a
`RESULT · none yet` row that fills when the program ends. The foot gives the
budget. The block names no file and claims no vetting, since a program has no
name and vetting is known only once a result says so; the program's elapsed
time is on the input frame's top rule (`◐ code_mode · 1.2s`), which the
activity already drives, rather than on the block, whose rows are cached. At 80 columns the fragment shrinks. The program text is
`transcript_lines.code_mode_program`
(`packages/session_view/src/session_view/transcript_lines.gleam:2397`)
(`code_mode_program`) and the result is drawn by `code_mode_result_lines`
(`packages/session_view/src/session_view/transcript_lines.gleam:2834`)
(`code_mode_result_lines`).

![Code mode today, 120x40](terminal-design/terminal-design-codemode-today-120-dark.png)

![Code mode today, 80x24](terminal-design/terminal-design-codemode-today-80-dark.png)

**Needs protocol-change 060.** A's summary (`7 calls · 1 failed · 2 not run`),
and B's calls grouped by capability with a count (`cap/fs.read ×3`), a failed
call with its exit status, and a running call. The settled row gains a call
count. The fragment above the calls is the same as today's. The call list needs
a record on the wire, which is what 060 adds.

060 writes the record on a program's result and nowhere else, so until a live
feed of calls lands the list appears on settled and stopped programs only: a
block still awaiting its result has none, which the frames above, drawn as the
target, do not show. `not run` is not a status the record carries either; it
has `ok`, `failed`, `cancelled` and `unsettled`, and the summary counts those.

## 8. Images

A tool result owns the images the tool returned, and `fs_read` of an image file
returns one (`packages/tools/src/tools/fs.gleam:963`) (`ToolResultImage`). So an
image appears wherever a tool returns one, under the call that returned it, and
not only when a person attached it. `transcript_image.of_entry`
(`packages/session_view/src/session_view/transcript_image.gleam:49`)
(`of_entry`) already yields the bytes for a user message or a tool result; the
`Image` type is at `packages/session_view/src/session_view/transcript_image.gleam:29`
(`Image`). Today the line builders draw a row of text, `[image image/png]`
(`packages/session_view/src/session_view/transcript_lines.gleam:2300`)
(`UserImage`). An assistant message carries no image block, so a model's own
generated image is out of scope until the message type has one.

Three cases, and one placeholder row that is always correct and always kept, so
scrollback, a recording replay and `loom replay` stay text:

- **Capable terminal.** A labelled box reserves at most 12 rows by 60 columns
  under the tool row, and the terminal fills it. The label gives the type,
  dimensions and size; the foot gives the keys.
- **No graphics reply.** The placeholder row: name, type, dimensions, size, `o`
  to open externally, and a line saying the terminal answered no graphics query.
- **Inside Herdr.** The same placeholder, saying pane graphics are not passed
  through (Herdr removed its pane-graphics API in 0.9.3).

**Detection without guessing.** The client asks and believes only a positive
answer. For kitty graphics it sends a one-pixel query (`a=q`) followed by a
primary device attributes request and reads the replies within 200 ms; a reply
to the second without the first means no support. iTerm2 does not answer that
query, so the client also sends the terminal-version request and accepts OSC
1337 only when the reply names iTerm2. `TERM_PROGRAM` is a reason to ask, never
the answer. The query is skipped, and the answer is none, when `HERDR_ENV` is
set, under `NO_COLOR` or the plain palette, and inside tmux unless the reply
comes back through it. The result is read once at launch, before the alternate
screen, and kept in the model.

**Scrollback and resize.** A placement is removed when its row scrolls out of
the region the renderer paints and drawn again when it returns. Where the
protocol has Unicode placeholder cells (kitty) the box is made of them, so it
reflows with the text. Otherwise a resize deletes the placements and redraws
them from the retained image after layout settles, and the placeholder row is
what the person sees in between.

There is no braille preview. It needs a pixel decoder the client does not have,
and all three concepts recommended leaving it out. Query, reply parsing,
placement and deletion belong in `../etui`, so that work is its own slice
(section 12). `o` writes the bytes to a private temporary file and hands it to
the platform opener the `loom ui` link already uses (`opener_for`,
`packages/tui/src/tui/view_link.gleam:83`) (`opener_for`).

**As built (slice 11).** The probe, the box and the commands are in
`packages/tui/src/tui/image_support.gleam`, `image_box.gleam`,
`image_shown.gleam` and `image_plan.gleam`, and `packages/tui/CLAUDE.md`
("Drawn images") says how they fit. Three things differ from the frames above.
The frame hugs the box, as wide as the picture or its label needs, rather than
spanning the pane, and the picture is centred in it. The box's foot offers only
`o opens externally`, because no key selects an image yet. The picture takes
about half the transcript, taken from the terminal's own height so that typing
never resizes it (at least 3 rows, at most 12), so an 80 by 24 terminal, which
has 19 transcript rows, gets a 9-row picture and still shows the
text around it. Two images in a row have one blank row between their boxes. A terminal that answered no graphics query shows the placeholder row alone,
with no line saying so, so that a replay and a live session show the same row.
And kitty and Ghostty draw PNG only, since their transmission carries the file
as it is: a JPEG or GIF keeps the placeholder row with a line saying so, and
iTerm2 draws all three. An image over 4 MiB decoded is never sent and says so
the same way.

**Layout memory.** What is remembered: whether the rail is docked, its tab, and
whether the todo line is expanded. What is not: the focused strand and the
session. The file is `<state-dir>/tui/layout.json`, keyed by the workspace root,
capped at 64 workspaces, read once at launch through the bounded read
`workspace_file.read_small_regular`
(`packages/tui/src/tui/internal/workspace_file.gleam:8`) (`read_small_regular`)
with a total decoder that returns the defaults for a missing or malformed file.
A change is a `SaveLayout` effect, so the step stays pure, and a replay neither
reads nor writes it. It needs no new FFI, because `simplifile` is already a
dependency.

*As built (slice 12).* The key is the lower-case SHA-256 of the workspace path,
the same construction as the daemon's web digest, over the terminal's discovered
workspace root made absolute, so a path is never written. The daemon hashes the
canonical workspace directory it was given, which can differ from the terminal's
discovered root, so the two stores keep separate keys and nothing relies on them
matching. The file is read with the launcher's
`read_private_bounded` rather than `read_small_regular`, which also refuses a
file another user owns or can read, and written with `atomic_write_private` in a
`0700` directory, and the JSON is `core/json`'s, so `tui` gains no dependency and
no FFI. The file is `{"version":1,"workspaces":[{"key":...,"rail":...}]}`, newest
first, and only the rail choice is stored today: the rail's tab and the todo line
do not exist until slices 13 and 14, and each will add one optional word, which
an older terminal ignores. A save re-reads the file and rewrites only its own
workspace's entry, so two terminals keep each other's workspaces; on one
workspace the later change wins. `packages/tui/CLAUDE.md` ("Layout memory") has
the rest.

## 15. Open questions

Each has a recommended answer.

1. **When does the rail dock by default?** Recommended: at 160 columns and
   wider, 56 cells; `Shift+Tab` docks it at 120 and wider (44 cells); a
   remembered choice wins. A proposed 200 only, and B proposed 160; 160 leaves
   a 103-cell transcript.
2. **While the rail shows Strands, does `↓` from the composer focus the rail?**
   Recommended: yes, because the strip is hidden and nothing else is below the
   input.
3. **New `F` keys for the tabs?** Recommended: no. Keep `Ctrl+O` and `F2` for
   the workspace, add `/trace` and `/summary`, and revisit function keys after a
   check that Herdr and common terminals pass them through.
4. **Strand focus from the timeline: `Ctrl+T` hint numbers (A), a timeline
   cursor (B), or neither?** Recommended: neither for now. The Strands tab and
   the strip already focus a strand, and a transcript cursor is a third keyboard
   owner. Revisit after slice 13.
5. **File protocol-changes 059 and 060 as separate proposals?** Recommended: yes,
   as already done. Slices 6 and 8 wait on each.
6. **`Tab` in the agent workspace.** Recommended: `Tab` cycles the filter, as in
   the picker, and `Esc` returns to the composer, which is what `Tab` does there
   today.
7. **Harness notice without a marker?** Recommended: do the data check in slice 3
   first. If the notice is an unmarked user entry, ship the repeat collapsing
   now and file the marker as its own protocol-change.
8. **A "last active" column in the picker?** Recommended: not now. It needs a
   field on `sessions.activity`; creation age covers the common case.
9. **Layout memory in a state-root file rather than the daemon?** Recommended: the
   file, because the layout is presentation and another machine may want
   another layout.
10. **Ask for images inside Herdr?** Recommended: no. Text only inside Herdr until
    Herdr documents pass-through; a query that reaches a pane and not the screen
    is a guess.
11. **Do model-generated images matter?** Recommended: not yet. An assistant
    message carries no image block, so only tool results and attachments draw an
    image; revisit if the message type gains one.
12. **Peers in the rail?** Recommended: yes, as a read-only `PEERS` section, since
    a peer's question is otherwise visible only as one transcript row.
13. **Three strand hues or more?** Recommended: three (cyan, violet, green)
    beside amber and red, which carry operator action and failure. A name always
    appears beside a hue, so colour never carries identity alone.
