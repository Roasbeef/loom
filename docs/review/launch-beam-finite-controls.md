# Finite Launch controls over TLS BEAM

The endpoint keeps one trusted registration for each original scope. Its optional
whole Launch owner shares that row with native, workspace and Compile services.
`beam_endpoint.attach_launch` checks the exact native handle and full scope;
when Compile is present, it also checks pinned enrollment and the original live
resource-writer PID. The PID projection grants no resource-journal authority.
Administrative assembly publishes this checked row after its concrete owners.

Route four carries the closed `LLQ` version-one operations: ChallengeRequest,
PlaceToken, Query, Cancel, Acknowledge and RefuseBeforeNative. First admission and
placement use Data; the remaining operations use Control. Existing route bytes
are unchanged, and route five is rejected until the separate finite stream bind
is implemented. RefuseBeforeNative carries canonical original input and maps to
one fixed diagnostic. Only a definite original owner clearance refusal can
justify invoking it; a lost reply or timeout cannot.

Every operation retains the full original ServiceKey and canonical LaunchInput,
including enrollment and token commitment. PlaceToken alone prefixes that input
with exactly 32 private token bytes. Ordinary metadata, historical Ready and
completion bytes never carry the token. The placement wrapper does not change
the immutable input digest. Existing aggregate ceilings apply before receiving
content; this route adds neither larger transfers nor a generic streaming layer.

Launch has one stable reply subject in each of the existing six endpoint credits.
An actual service answer clears its pending ask, while transport independently
requires `weft.AllDelivered`. Caller timeout cannot return the credit while its
ask is still queued. Launch owner loss or uncertain service custody permanently
retains the original assignment. `inspect_drain` keeps its finite-credit meaning:
only a fenced row without assigned or lost credits is Drained. It establishes
neither live-stream drain nor native retirement or resource cleanup.

Physical CompileCommand and SatelliteCommand use their respective whole owners.
The Launch owner retains the live Claim route; missing ownership never falls
back to generic native dispatch. Replies contain checked history only: full key,
pinned scope and enrollment, Launch Ready with the exact producer committed in
original canonical LaunchInput, and exact completion bytes with their
actual digest and receipt. Decoding history creates no Connection, live Claim,
or local journal COMMIT handle.

The real two-node fixture exercises Launch Challenge, token-placement refusal,
Query, a missing Claim's physical-command refusal, all six requests queued at a
suspended Launch owner, and loss of that owner with a retained finite assignment.
It preserves the existing native and workspace controls. Codec controls vary
namespace, budget, canonical framing, full identity, enrollment scope, Ready role,
and completion digest. These component controls do not establish live streaming
or complete remote product assembly.
