# Exact original Launch helper retirement

A Launch owns one borrowed helper until both the existing native retirement
boundary and the original helper owner's normal exit are observed. Terminal
bytes, successful Query and an absent inventory entry cannot discharge that
custody. Compile and ordinary native dispatch keep helper reuse. Each Launch
pays for one helper restart through the same open pool.

The approved contract is the retirement addendum in
[protocol 067](../../protocol-change/067-remote-workspace-services.md). The
[proposal](../design-notes/distributed-launch-native-retirement.md) records the
alternatives and the unchanged platform acceptance grade.

The pool registers an opaque `BorrowedRetirement` before dispatch, comparing the
exact pool, helper and original Borrowed entry. A lost registration reply
withdraws that same borrow; it never dispatches through an unconfirmed door or
checks the helper back in. Release, Abandon, relay loss and original adapter
death all trigger the same retirement door. Overlapping pool closure preserves
its observer.

| Original pool observation | Retained disposition | Publication |
| --- | --- | --- |
| Registered Borrowed entry | Exact observer installed | Registration only |
| Retirement requested | Draining | No positive proof |
| Positive native boundary | RetiringActor | No positive proof |
| Original normal owner Down | Exact retirement | One positive callback |
| Missing, foreign or abnormal witness | Unconfirmed | Uncertainty |

The remote native service installs its Row and original adapter monitor before
sending Begin to the parked adapter. The pool callback sends directly to that
Row, so adapter death cannot discard positive native proof. Actual adapter Down
ends control custody; it does not establish native retirement.

The Row confirms that exact proof with its immutable native key and prepared
digest. One managed task owns each confirmation ask, and actual AllDelivered
precedes promotion or a second ask. At most two asks share the original deadline
plus six seconds. This is observation grace, never renewed execution authority.
Scope closure refuses before journal writes while the original confirmation
continuation is in flight or its drain is lost. Scoped confirmation supplies
only scope proof; per-Launch notification has one path through the original Row
and its actual managed report drain.

Whole Launch waits within its existing fixed Closing lifetime when actual native
association has installed the retirement obligation. Resource release still
requires original preparation and transport joins, removal of the original
directory, ResourceOwnerCleaned COMMIT and continuation report drain. An
associated cancelled observation may release physical capacity after those
witnesses, while missing terminal or completion evidence stays uncertain in
immutable history. No history query recreates a Claim or Connection.

Focused controls hold the native boundary and original owner Down separately,
lose registration and confirmation replies, kill an actual original adapter,
overlap scope closure, and run more sequential Launches than one live slot can
hold. Fixture journals and unresolved paths are retained for inspection.
